# Batch 编码规范

适用于 `.bat`、`.bat.in`、`.cmd` 与 `.cmd.in`。先保持 VLink 既有
命令行接口、输出、退出码和执行顺序;不要以风格名义补整套防御逻辑。

## 1. 文件与命名

- 人工整改不触及第三方、预构建、构建目录与生成文件;显式调用
  `/format` 时仅按该 skill 和 `tools/format.sh` 的既定范围统一行尾。
- 入口使用 `@echo off`;需要隔离环境时尽早 `setlocal`,只在确有需要的
  最小范围启用 `EnableDelayedExpansion`。
- 按 `.gitattributes` 保持 CRLF 行尾。
- 使用 4 空格缩进。新增变量、标签与子程序先照相邻文件命名;不得为
  统一大小写或前缀改动既有名字和调用接口。
- 赋值一律使用 `set "NAME=value"`;不得使用会把尾随空格写入值的
  `set NAME=value`。
- 注释沿用文件现有的 `REM`、`@REM` 或 `::`;不要在风格整改中新增或
  改写注释。

## 2. 参数、路径与子程序

- 用 `%~dp0` 定位脚本目录,引用文件和可执行程序时始终给路径加引号。
- 参数解析、帮助和未知参数行为保持现有接口;新增参数时再补对应分支。
- 子程序的标签和 `call` 写法跟随相邻代码;新增子程序用 `exit /b 0`
  或原始失败码返回。
- `call` 会触发第二次展开;含用户输入、路径或 `%*` 的参数不得通过拼接
  后再次 `call`。必须保留原始引号边界,确需转发时逐项解析。
- `%VAR%` 用于普通块外展开;只有确需块内最新值时使用 `!VAR!`,并警惕
  路径中的 `!` 被延迟展开吞掉。处理外部参数或文件内容时先关闭延迟
  展开,只在最小代码块内重新启用。

## 3. 错误处理

- 本次确实需要传播失败的外部命令,沿用相邻代码的
  `if %ERRORLEVEL% neq 0`、`if errorlevel 1` 或保存状态写法;不要批量
  给原有每条命令追加检查。`if errorlevel 1` 表示大于等于 1;需要捕获
  任何非零状态时保留 `neq 0` 或先保存状态。
- `setlocal`/`endlocal` 跨边界返回状态或变量时,使用单条
  `endlocal & exit /b %_STATUS%` 或 `endlocal & set "NAME=%VALUE%"`,
  并在展开前保存值。
- 不改变既有可接受退出码;新增多命令步骤时再明确其失败边界。
- 管道、重定向和 `for /f` 会改变错误传播时,拆成临时文件或独立步骤。
- `%`、`!`、`^`、`&`、`|`、`<`、`>` 在参数、配置和 `for /f` 中均有
  特殊语义;不得用 `echo %VALUE% | findstr` 处理未验证的外部内容。
- 清理失败不得覆盖主要构建/发布失败;返回前保留原始状态。

## 4. 改动边界与验证

- 不新增缓存 marker、产物门禁、参数限制或逐命令失败检查,除非当前
  任务明确要求或已有失败样例。
- 新增 `rmdir /s /q`、`del /q` 时确认目标来自明确的项目目录;不要
  借整理现有脚本扩大清理范围。
- 维护者明确要求行为验证时,在 `cmd.exe /d /c` 中覆盖实际受影响的
  帮助、参数或错误路径;涉及构建/发布时只用 stub 或临时目录。
- 非 Windows 环境缺少 `cmd.exe` 时只做静态审查并明确标注未执行;
  最终验证必须由 Windows runner 完成。
