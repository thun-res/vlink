# Shell 编码规范

适用于仓库内 `.sh`、`.sh.in`、`.bash` 与 `.bash.in`,尤其是
`tools/`、`.github/scripts/` 与 `packup/`。本页记录现有脚本的共同
写法,不是重写清单。修改时先保持接口、参数、输出、退出码和执行顺序,
只整理本次触及的代码。

## 1. 文件与版式

- 人工整改不触及第三方、预构建、构建目录与生成文件;不得为统一风格
  修改外部代码或构建产物。显式调用 `/format` 时仅按该 skill 和
  `tools/format.sh` 的既定范围统一行尾,不授权改写 Shell 结构或注释。
- 新增独立 Bash 入口优先使用 `#!/usr/bin/env bash`;被加载的 completion
  片段不强加 shebang,既有入口沿用相邻文件。
- 按 `.gitattributes` 保持 LF 行尾。
- 注释沿用当前文件;风格整改不新增或改写说明性注释。
- 使用 4 空格缩进,不使用 Tab;续行参数比所属命令多缩进一级。
- 新增普通 Bash 函数优先使用 `function name() {`;已有函数的私有前缀
  和局部变量命名沿用当前文件与相邻脚本,不为统一大小写或下划线前缀
  改名。`tools/` 中新增的同类入口可参照 `update_version.sh`。
- 简单文件/字符串判断使用 `[ ]`;模式或正则匹配使用 `[[ ]]`;
  `case` 分支的 `|` 两侧留空格。

## 2. 路径与参数

- 需要脚本目录时沿用 `tools/update_version.sh` 的展开方式:
  `$(cd "$(dirname "${BASH_SOURCE:-$0}")" && pwd)`。变量名保持当前文件;
  `tools/` 中新增同类入口使用 `SHELL_DIR`,`.github/scripts/` 中新增入口
  沿用相邻文件的 `script_dir`。原脚本明确以仓库根为工作目录时保持原
  接口,不要顺手改成另一套路径模型。
- 路径和可能发生分词/glob 的命令参数展开必须加双引号,`"$@"` 与数组
  按 `"${ARRAY[@]}"` 展开;赋值、`[[ ]]`、算术和 `case` pattern 按
  Bash 语义书写,不得机械加引号或把参数拼成字符串后二次解析。
- 参数和帮助行为保持相邻入口的写法;不要为了“更严格”新增默认值、
  环境变量、参数分支或错误码。
- 新增临时文件使用 `mktemp`;只清理脚本自己创建的精确目标。

## 3. 状态与错误处理

- 独立 CI/发布入口可使用 `set -euo pipefail`;环境初始化脚本和可被
  `source` 的公共 helper 不得擅自改变调用者 shell 选项,全局变量必须
  使用项目名前缀。
- 不把 `set -e` 当成完整错误处理。修改函数或 progress wrapper 内的
  多命令步骤时,确认失败不会被后续成功掩盖;只在这个真实风险存在时补
  `|| return` 或清晰的 `if`。
- 预期失败使用 `if command; then ... else STATUS=$?; ... fi`,不得用
  `set +e` 扩大失效范围。
- 修改 EXIT trap 时保留原流程的退出码和清理范围;没有实际故障时不
  重写既有 trap。
- 不用真假值链拼接多步业务逻辑。需要分支或保留退出码时写完整 `if`。

## 4. 改动边界

- 不新增未被当前需求使用的缓存 marker、fallback 环境变量、额外产物、
  扫描范围、依赖白名单、重试或防御性校验。
- 不把一次赋值改成配置去重/原子替换,不把宽松解析改成严格解析,除非
  当前任务明确要求且有失败样例证明必要。
- `rm -rf` 保持既有已验证边界;新增删除操作时目标必须非空且属于明确
  的预期目录。
- 修复真实错误时只改最小 hunk,不要顺手统一同文件其他行为。只有维护者
  明确要求批量风格整理时才处理其指定范围,且不得借机改变量名、接口或
  行为。

## 5. 兼容与验证

- macOS 工作流脚本兼容系统 Bash 3.2:不使用关联数组、`mapfile` 等
  Bash 4+ 特性。
- Linux/macOS 差异写成显式平台分支;GNU-only 的 `sed`、`stat`、
  `readlink`、`mktemp` 参数仅用于已固定 Linux 镜像的脚本,否则提供
  macOS 分支。
- 最低验证为改动脚本 `bash -n`;维护者要求行为验证时,再用临时目录或
  stub 覆盖实际受影响路径,不扩展成另一套实现。
- `shellcheck` 可用时检查改动脚本;确属有意的例外只做最小范围、带规则
  名的压制,不得修改全局配置消音。
- 不为“测试脚本”执行真实发布、上传或破坏性命令。
