# 子代理编排与对抗复核

## 派发

- 按已固化的模块任务并行派发;超过并发上限时分批,不得通过合并不相干
  模块降低覆盖粒度。
- 每个 subagent 只读评审,禁止修改或创建仓库文件。
- 每个 subagent 先读根 `AGENTS.md`,再按文件类型加载对应分册。
- 指令必须附精确文件清单,要求逐文件返回“已检/跳过/无法检查”状态。
- 输出使用简体中文;每条发现包含行号、严重级、触发场景和影响。
- 共享工作区可能同时变化。文件在派发后被修改时,以最新内容重新审阅并
  标明版本变化;不得要求 subagent 恢复旧内容。主代理写报告前重新检查
  现状,使用独立报告文件,不得覆盖其他 Agent 的报告。

建议的任务指令骨架:

```text
只读评审以下文件,禁止修改仓库。先读 AGENTS.md 和对应分册。
逐文件检查正确性、并发、性能、接口和规范。
返回完整文件覆盖清单;每条发现写明 文件:行号、严重级、触发条件和影响。
没有证据的问题不要上报,无法检查的文件说明原因。
```

## 汇总与反驳

- 主代理对 P0/P1 逐条回读源码,确认行号、控制流和触发条件。
- 重要或跨模块结论交给未提出该问题的 subagent 反驳式复核,要求主动
  寻找误报依据、已有保护和反例。
- 反驳成立则删除或降级;证据冲突标记“待核实”,不得伪装成确定缺陷。
- 多个 agent 指向同一根因时合并,保留最清晰的触发路径和全部受影响点。
