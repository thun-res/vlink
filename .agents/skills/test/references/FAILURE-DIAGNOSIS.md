# 测试失败诊断

## 失败分层

按首个失败阶段定位,不要跳过前置失败:

1. **配置失败**:记录 CMake 错误、生成器、平台和关键开关;不使用旧产物。
2. **构建失败**:记录首个编译或链接错误及目标;后续测试结果无效。
3. **Proxy 失败**:检查平台 runner 指向的可执行文件和日志,确认进程是
   缺失、启动失败还是提前退出。
4. **CTest 失败**:记录失败 suite、失败断言、超时或崩溃信号,区分稳定
   失败与外部服务缺失。

## 复现原则

- 先用原命令复现首个失败,不要靠并行重跑掩盖问题。
- 需要缩小范围时使用 [TARGETED-TEST.md](TARGETED-TEST.md),并保留原
  全量失败结论。
- 不扩大排除正则、不放宽 Windows 容忍数、不删除断言,也不把重跑偶然
  通过写成已经修复。
- 失败依赖环境或外部服务时,明确列出缺失条件和未执行范围。

## 结果摘要

至少报告:

- 平台、构建目录和测试方式;
- 全量或定向范围、匹配数量、通过/失败/跳过数量;
- 首个有效错误和失败日志位置;
- 是否启动 Proxy、是否排除外部后端;
- 未执行的构建、平台或测试范围。
