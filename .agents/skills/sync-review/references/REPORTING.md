# 同步审计报告与处置

## 发现分类

- **遗漏**:缺文档、注释、绑定、测试、示例、索引或 CHANGELOG。
- **错误描述**:派生内容与代码或 `doc/` 事实矛盾。
- **陈旧引用**:路径、标题、小节、选项、版本或功能入口已失效。
- **待确认契约**:代码行为与产品语义冲突,无法仅凭仓库判断应修改哪侧。

每条发现附事实侧与派生侧的 `文件:行号`,说明影响和建议修改归属。

## 修复授权

- 用户只要求检查时不修改文件。
- 用户明确要求修复时,按事实基准修改直接受影响项,不顺手重写无关内容。
- 契约方向不明确或会扩大公开行为时停止修改,将证据列为待确认。
- 修复后重新检查受影响的双侧证据和链接,报告实际验证范围。

## 并行审计

全量审计可按 doc 章节与对应源码职责并行拆分。每个 subagent 必须只读、
输出中文,并为每条发现提供双侧行号。汇总时回读证据、去重,不能把分工
边界之间的派生面遗漏掉。

## 报告

用户明确要求落盘时写入
`.agents/cache-report/sync-review-<范围>.md`,结构为:

1. 范围、基线和排除项;
2. 遗漏;
3. 错误描述与陈旧引用;
4. 待确认契约;
5. 已核对且无需同步的项目;
6. 未执行的动态验证。

已落盘时最终回复摘要关键结论并给出路径;否则直接给出审计结论。
