# 生态与差异化

## 1. 选择比较对象

先按层级分组,不做一张失真的总排行榜:

| 层级 | 可能对象 | 比较重点 |
| ---- | -------- | -------- |
| 机器人应用框架 | ROS 2、Autoware、Apollo | 生态、开发模型、工具、治理 |
| 通信/RMW | DDS 实现、Zenoh 等 | QoS、发现、传输、互操作、部署 |
| 共享内存/IPC | iceoryx 等 | loan、内存模型、跨进程与平台 |
| 数据与可视化 | MCAP、Foxglove、Rerun 等 | 录制、schema、分析、协作 |
| 项目自研总线 | 公开案例 | 定制成本、可维护性、迁移成本 |

只有功能层级和目标用户接近时才使用"竞品";其余标为上层生态、底层依赖、
互补工具或潜在集成对象。

## 2. 比较维度

- API/编程模型与迁移成本;
- 传输、QoS、zerocopy、跨平台和实时路径;
- schema/序列化、录制回放、可观测性、CLI/GUI;
- 性能证据的硬件、版本、负载、消息大小和测量方法;
- 文档、示例、release、社区、治理、许可证和供应链;
- ROS 2/自动驾驶/具身平台的现成适配与实际案例。

同一维度至少引用双方一手证据;没有可比基准时只做能力矩阵,不下性能
胜负结论。

## 3. 优势、劣势、机会、风险

- **优势**:已经由当前代码、文档、CI 或可复现实验支持的能力。
- **劣势**:当前项目内部可观察的缺口,如生态、验证、平台、治理或工具。
- **机会**:行业需求与 VLink 已有能力之间存在可执行连接。
- **风险**:外部替代、标准演进、维护集中、认证、集成成本或定位模糊。

每条标注证据、影响范围、置信度和反例。优势不能只改写 README 卖点,
风险也不能凭主观印象夸大。

## 4. 定位结论

最终给出:

1. 当前最可信的核心用户与场景;
2. 应坚持的差异化边界;
3. 不应投入或暂不应宣称的方向;
4. 与 ROS 2/Autoware/Apollo/Zenoh/DDS/iceoryx/可视化工具的优先关系;
5. 需要用真实用户、集成或基准验证的关键假设。
