# 报告结构

报告写入 `.agents/cache-report/report-vlink-<YYYYMMDD>.md`,使用以下
固定结构。

## 1. 摘要

- 截止日期、HEAD、版本和证据范围;
- 一句话定位;
- 当前阶段判断;
- 三项机会、三项风险、三项优先建议。

## 2. 项目现状

- 能力地图与明确边界;
- 30/90/365 天活跃度、release、Issue/PR、贡献者和 CI;
- 产品、工程、性能、兼容、生态、治理六维成熟度。

成熟度可用 0–5 分,但每分必须紧邻证据和缺口;总分只作摘要,不能掩盖
关键短板。

## 3. 行业与生态

- 具身智能;
- 自动驾驶;
- ROS 2 与通信基础设施;
- 数据闭环和可视化;
- 分层比较矩阵与 VLink 的竞争/互补关系。

所有时效事实带发布日期/访问日期和链接。

## 4. 优势与劣势

分别列:

- 已验证优势;
- 当前劣势;
- 潜在机会;
- 外部与内部风险;
- 反方观点与可能推翻结论的证据。

## 5. 建议路线

按近期、中期、长期排序。每项包含:

| 字段 | 内容 |
| ---- | ---- |
| 问题/机会 | 来自哪条发现 |
| 建议 | 具体动作 |
| 价值 | 用户或项目收益 |
| 成本/依赖 | 人力、技术、生态前提 |
| 风险 | 可能副作用 |
| 验收 | 可观测结果或停止条件 |

优先级使用 P0/P1/P2 或 Now/Next/Later,但不得同时堆两套体系。

## 6. 证据与限制

- 仓库与 GitHub 查询口径;
- 外部资料清单;
- 无法访问、未验证和存在争议的事项;
- 事实、推断、建议的标识说明。

最终做一次引用核对:每个关键数字和当前状态都有来源,链接直接指向支持
该结论的页面,无断链、无搜索结果页、无超长引用。
